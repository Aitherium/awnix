awnix

A Linux you can hand to an agent.

Not a distro with an AI assistant bolted on. A bootable, immutable base for machines where software writes software — and where you still need to know what happened, undo it, and prove it.

$ podman build -t awnix:latest -f Containerfile .

That's the install. The OS is the container image.

Give an agent real access and you inherit four problems

Not eventually. On day one.

01 / VISIBILITY

It will change things you can't see

Not maliciously — thoroughly. An immutable /usr and atomic updates make every change a new image you can diff, and a bad one is bootc rollback, not an evening.

02 / CONCURRENCY

It will run alongside other agents

Two processes editing one file isn't a merge conflict, it's lost work. Which is why the tooling has leases, and why they're taken before the edit, not after.

03 / FALLIBILITY

It will be wrong sometimes

The question was never whether. It's whether you find out cheaply. Snapshots and verified artifacts turn "what did it actually do" into a command instead of an investigation.

04 / CREDENTIALS

It will need credentials, and shouldn't get yours

awnix ships no password at all. The account is locked, access is by injected SSH key, and there's nothing to leak because nothing was ever set.

On someone else's platform, all four are handled by trusting the platform. awnix is the other bet: you can verify everything, so you have to trust nothing.

What's actually in it

podman, buildah, skopeo and crun for rootless containers. cloud-init, so a key-only image is genuinely reachable. Cockpit on 9090 for a machine with no desktop. firewalld with an awnix zone and zero ports opened — opening one is a decision about what you're running, and a base image that guesses will either block you or expose you.

No services. No agent. No account. What runs on top is yours.

Four opinions, each learned the expensive way

state under /var An immutable /usr loses anything else on update.
a real healthcheck Without one, a wedged container looks exactly like a healthy one to every supervisor on the box.
Restart=unless-stopped Nothing revives an exited container — and this still honours a manual stop.
After=network-online The difference between a network that is configured and one that merely exists.

The aw family

awnix is the ground floor. The rest stand alone — each installs on its own, each works offline, none needs an account. The pattern, in one sentence: every one replaces something you'd otherwise have to trust with something you can check.

awgit

git with leases, so two agents in one worktree don't silently overwrite each other's work.

awgraph

A semantic code graph — AST + tree-sitter, call graphs. An agent reads structure instead of grepping.

awseal

Sign a directory so a stranger can verify it. The key that verifies is not the key that forges.

awshare

Publish an artifact and fetch it back verified — content-addressed bundles.

awrelay

Agent messaging — findings, alerts, coordination — without a SaaS in the middle.

awm

Scoped agent memory: tenant:user:project, so a write can't leak across a boundary.

awrecover

Labelled snapshots, with a restore that fully lands or doesn't land.

awnix

The ground floor. Boots, runs containers rootlessly, updates atomically, ships nothing else.

Make it bootable

One image, every format. AMI, ISO, qcow2, vmdk, raw.

podman run --rm -it --privileged \ -v /var/lib/containers/storage:/var/lib/containers/storage \ -v "$PWD/output":/output \ quay.io/centos-bootc/bootc-image-builder:latest \ --type ami --local awnix:latest

Then bootc upgrade to stage, reboot to switch, bootc rollback if it went badly.

Source Apache-2.0 bootc

awnix is the OS layer — deliberately small, deliberately opinionated about the few things that are expensive to get wrong, and silent about everything else.
